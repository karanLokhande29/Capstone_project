### 1. LLM client `src/llm/client.py`
- **Providers:** free tiers only, no OpenAI.
  - **Primary:** Gemini (`GEMINI_API_KEY`).
  - **Fallback:** Groq (`GROQ_API_KEY`), used only on rate-limit or quota errors.
- **Models:** list the available models at startup; don't hard-code names. Pick a current text model for `llm.model` and the longest-context Gemini model for `llm.long_context_model`. Write both into config, and record the exact model ids and version strings the APIs return.
- **Calls:**
  - temperature 0;
  - a disk cache keyed on the hash of (provider, model, messages, params), under `data/llm_cache/` (gitignored);
  - client-side throttling from config (requests per minute, tokens per minute);
  - exponential backoff on 429;
  - a hard cap on calls per run (`llm.max_calls`);
  - a log of each call's provider, model and token counts.
- **Never mix providers within one system run.** If a fallback happens mid-run, report it and mark the run.

### 2. T2 relevance sets → `data/benchmark/t2/`
Build each set separately and never pool them. Each has a **known bias**, and the report states it.
- **`t2_xclass_t1`** (main): from `data/benchmark/t1/t1_validated_v1.jsonl`.
  - Query = the source obligation text, with the target class.
  - Relevant = the final `matched_paragraph_id`: grade 2 if `same`, 1 if `different`. `none` gives no relevant paragraph.
  - *Bias:* the shown candidates were bge top-1/top-2, which favours the dense retriever, though raters could look up any paragraph.
- **`t2_xclass_p2002`**: from the 60 P2-002 validation pairs.
  - Query = the source obligation text, with the target class.
  - Relevant = the target paragraph: grade 2 if `same`, 1 if `related`. `unrelated` pairs are dropped.
  - *Bias:* pairs were drawn by bge semantic bands, which favours the dense retriever (same model).
- **`t2_supp_p2003`**: from P2-003 alignment rows labelled `paragraph` or `multi_paragraph`.
  - Query = the item text (penalty deficiency or FAQ Q&A).
  - Relevant = the chosen paragraph ids (grade 2).
  - Target class = the resolved entity class, if any.
  - *Bias:* candidates were shown by TF-IDF, which favours BM25.

### 4. Retrieval systems (top 100 kept for each)
- `bm25`;
- `dense` (class-blind);
- `hybrid_rrf` (k = 60, BM25 + dense);
- `class_aware`: hybrid RRF restricted to paragraphs whose Direction's entity class equals the query's target class, when one exists (otherwise the same as hybrid, and flagged).

Always exclude the query's own source paragraph from its results.

### 5. Scoring → `reports/p3001_retrieval_baselines.md` and `reports/p3001_metrics_v1.json`
- Per system and relevance set: Recall@10, MAP@10, nDCG@10 (graded), each with n and a seeded 2,000-resample bootstrap 95% CI over queries.
- **Paired** bootstrap differences for hybrid vs BM25, hybrid vs dense, and class-aware vs hybrid (the ablation A preview).
- A per-target-class breakdown where n ≥ 5.
- State each set's bias next to its results. Don't declare a winner across sets.
- Record the environment: machine, OS, Python and package versions, device, model revision, LLM model ids.

### 6. T1 baselines `src/eval/t1_eval.py`, on `data/benchmark/t1/t1_validated_v1.jsonl`
- **Metrics:** Macro-F1 on `differential_flag`, per-class F1 on per-class judgements, the confusion matrix, and bootstrap CIs.
- **Majority-class baseline:** predicts the majority flag and majority per-class judgement, with the majority taken from the validated set itself; this is stated.
- **P2-002 candidate labels** as the "dense within-family" baseline:
  - `matched` is read as a counterpart (`same` or `different`, which it can't tell apart), `below_threshold` as `none`;
  - its flag is only `absent` or `shared_or_class_specific`, and the report explains how that is scored.
- Output: `reports/p3001_t1_baselines.md`.
