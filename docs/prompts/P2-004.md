## F. Objective
1. Build the **T1 candidate benchmark** for every eligible obligation. It carries automatic candidate labels derived from P2-002 matches, plus entity-class and temporal metadata for filtering.
2. Draw a **validation sample** sized from the annotation budget. Karan labels it blind (pass 1). Karan then re-labels a hidden retest subset at least 5 days later (pass 2), along with the 18 pilot items that were never retested. Akash and Meer label a second-rater subset from **blank** files.
3. Compute test-retest and inter-rater reliability, adjudicate disagreements in writing, and produce the **validated T1 set** with a validation route in `provenance` for every item.

Candidate and validated data stay in separate files throughout.

### Part A — Claude Code, local

**A1. Preflight.** Verify all of the following and **stop** if any differs:

**A2. Label rules check (stop point).**
- Read the guidelines. Write out the exact definitions they give for `applies_to`, `differential_flag` (`shared` / `class-specific` / `absent`), `notes` and `applies_to_rationale`.
- This prompt proposes the per-class judgement and mapping below. Compare it with the guidelines. **If they conflict, stop and show both; the guidelines win unless Karan decides otherwise.**
- **Per-class judgement** (one per compared target class):
  - `same`: the same obligation applies;
  - `different`: the same topic, but the requirement differs (threshold, timeline, scope);
  - `none`: the target class's Directions in this family contain no corresponding obligation;
  - `unsure`: the rater can't tell.
- **Derived labels:**
  - `applies_to` = {source class} ∪ {classes judged `same` or `different`};
  - `differential_flag` = `shared` if every compared class is `same`; `absent` if every compared class is `none`; otherwise `class-specific`;
  - any `unsure` → the item is flagged `ambiguous` and goes to adjudication.
- **Compared classes** are target core classes with status `scored` for that source. Classes with `no_direction_in_family` are **not compared**. They are recorded as such, never as `none`, because the counterpart may sit in another family (3.5% leakage in P2-002).

**A3. Candidate benchmark** → `data/benchmark/t1/t1_candidate_benchmark_v1.jsonl`, one record per eligible, non-boilerplate core candidate.
- Automatic candidate labels (all marked `label_status: candidate`):
  - `applies_to_candidate` = {source} ∪ {target classes with status `matched`};
  - `differential_flag_candidate` from the A2 mapping, treating `matched` as `same`-or-`different` (it can't tell them apart) and `below_threshold` as `none`.
- **Temporal metadata**, deterministic only:
  - `in_force_from` = the Direction's issue or consolidation date, or its "(Updated as on …)" stamp;
  - `amended_by` = a list of amendment `item_id`s whose cited paragraph numbers match this paragraph's clause path;
  - `in_force_to` = null unless an amendment explicitly deletes or substitutes the paragraph.
  - Report coverage for each field. No inference beyond this.
- **Filtering metadata:** `entity_class`, `subject_family`, `section_id`, `clause_path`, `md_id`, `era`.
- Carry `source_candidate_id` and the P2-002 top-1 target per class.

**A4. Size.** Recompute §K's numbers from config (`t1.annotation_hours`, `t1.minutes_per_item`, `t1.retest_fraction`) and print the calculation. Defaults: 10, 3.61, 0.20.

**A5. Draw the validation sample** (seeded) → `data/benchmark/t1/p2004_sample_v1.jsonl`.
- **Pool:** candidate-benchmark records with ≥ 2 compared classes. Exclude pilot items, boilerplate and any candidate in a P2-002 validation pair.
- **Stratify by source class:** proportional, with a floor of 6 per core class that has ≥ 6 eligible candidates. Within each class, spread across subject families and across the candidate flag.
- **Compared classes per item:** at most **K = 4**, chosen by seeded random from that item's `scored` classes (config `t1.max_compared_classes`). This keeps an item near the measured pace. `applies_to` is then over the compared classes, and the report says so.
- **Order:** pre-shuffle into a **stratum-interleaved order** in blocks of 20, so any prefix of whole blocks stays roughly stratified. If time runs out, pass 1 stops at a block boundary and the sample is the labelled prefix.
- **Retest subset:** a stratified random 20% of the sample, spread across blocks (so truncation keeps about 20%), drawn **now** and written only to the hidden key. The 18 pilot items are added to pass 2 automatically.
- **Second-rater subset:** 30 items from the first 3 blocks, stratified, in the hidden key.

**A6. Annotation files** (reuse the P1-005 writers, BOM-safe).
- **Pass-1 sheet** `annotation_p2004_karan_pass1.csv`, long format: one row per (item, compared class). Shown columns:
  - `item_id`, `block`, `source_class`, `subject_family`, `source_span` (the obligation sentence(s) with the paragraph text);
  - `target_class`, `target_candidates`: the top-1 **and** top-2 target paragraphs from P2-002 for that class, ids plus text, in shuffled order, with no scores, band, status or candidate labels;
  - `judgement`, `note`, left blank;
  - one item-level `applies_to_rationale` row per item.

  Karan may cite any paragraph via the `lookup` helper from P2-003.
- **Second-rater sheets** `annotation_p2004_akash.csv` and `annotation_p2004_meer.csv`: the same format, only the 30 subset items, and **blank**. The tooling refuses a second-rater file whose judgement cells arrive pre-filled from another rater's file (the D11 guard).
- **Minutes log** `p2004_minutes.csv` (`rater, block, started_at, ended_at, minutes, note`). Karan fills in one line per block as he works.
- **Hidden key** `p2004_key_v1.json`: candidate labels, P2-002 scores and statuses, strata, retest and second-rater membership. No rater opens it.

## P. Data Schema
**Candidate benchmark record:** `item_id, source_candidate_id, md_id, entity_class, subject_family, section_id, clause_path, obligation_span, compared_classes, not_compared: {class: "no_direction_in_family"}, applies_to_candidate, differential_flag_candidate, per_class_candidate: {class: matched|below_threshold}, top_targets: {class: [ids]}, in_force_from, in_force_to, amended_by, era, label_status: "candidate", provenance: "auto:p2002_matches_v1"`.

**Validated record:** the same keys plus `applies_to, differential_flag, per_class_judgement, applies_to_rationale, ambiguous, label_status: "validated", provenance: <route>, raters: {...}, label_source: "manual"`.
