## E. Model To Use
**Opus.** This prompt makes matching-design and threshold judgements that decide what counts as "the same obligation" across entity classes. That is the core of RQ2.

## F. Objective
For every kept candidate obligation (P2-001, rules v4), find the best counterpart candidates in the **other entity classes' Directions on the same subject family**. Record how strong each match is and what kind it is. Then measure, against Karan's blind judgement, how reliable those matches are.

This step produces **candidate** matches only. It assigns no `applies_to` or `differential_flag` labels.

## H. Why This Step Exists
RQ2 asks what one entity class must do that another need not. That needs, for each obligation, its counterpart (or the absence of one) in each other class's parallel Direction. Positional alignment failed the 60% trigger in Phase 1, so counterparts must be found by content. How reliable that is has to be measured, not assumed.

**A2. Matching units.** For each kept candidate, extract the sentence(s) containing each **kept** cue. Excluded cues contribute nothing. Record character offsets within the paragraph.
- If a paragraph has one kept cue and is under 400 characters, the whole paragraph is one unit.
- Record units that exceed the embedding model's token limit; they are truncated, not dropped.

**A3. Blocking.** Build comparison blocks: same derived `subject_family`, different core entity class.
- Candidates with no subject family, or in a function-heading class, are **not** matched.
- Count them and report them by class.

**A4. Stage 1: repeated wording.** Use `near_duplicate_clusters()` across core classes within each block.
- Pairs in the same cluster get `match_type = exact` (identical after normalisation) or `near_duplicate`.
- Report the clusters that span ≥2 core classes, with the distribution of how many classes each spans. **This is a headline descriptive finding:** how much of the parallel text is shared word for word.

**A5. Stage 2: semantic** (runs on Kaggle; see Part B).
- Embed every matching unit with `BAAI/bge-base-en-v1.5`, pinned to the exact revision hash, normalised embeddings.
- For each source candidate and each **other** core class that has candidates in the same block, take the paragraph-pair score as the **max** cosine over their unit pairs. Keep the **top 3** targets per target class and record which unit pair produced each score.

**A6. Baseline.** For the same pairs, compute a lexical score: TF-IDF cosine on the same units, fitted on the whole candidate unit set. Report agreement between the semantic and lexical rankings (top-1 agreement rate). On the validation sample, report both methods' precision at matched coverage.

**A7. Status for every (source, target class) combination:**
- `scored`: target class has candidates in the block;
- `no_candidates_in_family`: target class has a Direction in this subject family but no kept candidates in it;
- `no_direction_in_family`: target class has no Direction in this subject family.

The last two are different kinds of absence, so keep them separate. **Apply no threshold in this pass.**

**A8. Blocking leakage check** (on Kaggle, embedding space).
- Draw 200 random core-class candidates (seeded) and search all other core classes **without** blocking.
- Report the share whose best cross-class match lies **outside** their own subject family and scores at or above the high-band lower edge (defined in C1).
- This estimates how many counterparts subject-family blocking misses.

## P. Data Schema

**Match record** (one per source candidate × target core class):
```
source_candidate_id, source_entity_class, subject_family, target_entity_class,
status: scored | no_candidates_in_family | no_direction_in_family,
top_targets: [ {candidate_id, semantic_score, lexical_score,
                match_type: exact | near_duplicate | semantic,
                source_unit_offsets, target_unit_offsets} ] (up to 3),
near_dup_cluster_id (nullable), margin_top1_top2 (nullable),
model_id, model_revision
```
After Part D, the thresholded file adds `status: matched | below_threshold` for `scored` rows, and records `threshold_value` and `threshold_source: "p2002_validation_v1"`.

## Q. Implementation Logic
- Normalise text for stage 1 the same way `near_duplicate_clusters()` does.
- Cosine on L2-normalised embeddings.
- Paragraph score = max over unit pairs. Ties are broken by lexical score, then by `candidate_id`.
- Everything is seeded and deterministic. Re-running on the same inputs reproduces the files byte for byte (the embeddings file is exempt).
