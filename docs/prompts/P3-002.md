## RQ3
Does the documented gameability of RePASs reproduce on Indian regulatory text, and what minimal repair resists concatenation and verbatim extraction?

Prior evidence, for context only (don't assume the result): on ObliQA, a naive obligation-concatenation system scored RePASs 0.947, above human experts (AUEB-Archimedes at RIRAG-2025, arXiv 2412.11567).

## Tasks

### 0. P3-001 follow-ups (small; do these first)
- **a. BM25 vs dense.** Add the paired bootstrap difference (2,000 resamples, seeded) for BM25 vs dense on all three relevance sets to `reports/p3001_retrieval_baselines.md` and the metrics JSON.
- **b. Framing of the class-aware gain.** Add a paragraph above the class-aware results. Relevance was labelled only for the counterpart in the query's target class, so the task is *retrieval of the target-class counterpart*, and class-blind systems are partly disadvantaged by construction. The class-aware gain shows the value of knowing the target class for this task; it is not a general class-blind vs class-aware verdict.
- **c. A fairer diagnostic,** reported separately: class-blind hybrid with paragraphs from the **query's own source class** removed from its results (`hybrid_minus_source_class`). Report it next to hybrid and class-aware on all three sets.

### 1. RePASs
- Clone `https://github.com/RegNLP/RePASs` into `external/RePASs` (gitignored), and pin the commit hash.
- Read its code. Record in the report the exact NLI model id, the obligation-classifier base model, and the composite-score formula as implemented.
- Train the obligation classifier with the repo's own `scripts/train_model.py` on its own dataset, **unchanged**. Use MPS if available, and seed everything. Record the runtime and the device.
- **Don't modify their scoring code.** Score through a wrapper that calls their evaluation logic and writes their JSON format (`QuestionID`, `RetrievedPassages`, `Answer`).

### 2. Questions (n = 30, seeded) → `data/benchmark/t4/`
- Sample 30 obligation paragraphs from the **T1 validated set** (`t1_validated_v1.jsonl`, `label_status: validated`, not `not_obligation`):
  - across at least 6 core classes and at least 10 subject families;
  - stratified by class in proportion to the validated set, with at least 1 per sampled class.
- The LLM drafts **one question per paragraph**: one a compliance officer of that class would ask and that the paragraph answers. Log the prompt, the model id and the output.
- **Retrieved passages:** the class-aware hybrid top 3 from P3-001, plus the source paragraph if it isn't already in the top 3. Record the retrieval rank of the source paragraph.

### 3. Answers: four types per question, each saved to its own file
- **`genuine`:** the LLM writes an answer from the passages only, citing `[paragraph_id]`, at temperature 0.
- **`concatenated`:** no LLM. Verbatim concatenation, in passage order, of every sentence in the passages that contains a kept deontic cue (the P2-001 cue list). This is the naive obligation-concatenation strategy.
- **`adv_negated`:** the concatenated answer with deontic polarity flipped (`shall` ↔ `shall not`, `must` ↔ `must not`, `is required to` ↔ `is not required to`) and every number doubled.
- **`adv_offtopic`:** verbatim obligation sentences from a seeded random Direction in a **different** subject family, matched to the concatenated answer's length.

### 4. RePASs scoring
Score all 4 × 30 answers. Save the raw per-answer entailment, contradiction, obligation-coverage and composite scores.

### 5. Human faithfulness sheet → `data/benchmark/t4/t4_faithfulness_sheet_v1.csv`
- **30 answers,** stratified: 10 genuine, 10 concatenated, 5 adv_negated, 5 adv_offtopic.
- **Blind:** shuffled, with answer type, scores and model hidden (the key is a separate file).
- **Columns:** question, the retrieved passages (ids and text), the answer, then blank `faithful`, `answers_question`, `bad_question`, `note`.
- **Header note for Karan:**
  - `faithful`: 2 = every claim supported by the passages; 1 = partly; 0 = unsupported or contradicted;
  - `answers_question`: 2 / 1 / 0;
  - `bad_question`: yes if the question itself is flawed;
  - no AI tools; log times per block.
- **Blocks:** 3 blocks of 10. Write the minutes log `t4_faithfulness_minutes.csv` (block, started_at, ended_at).
- **Ingest:** accept the completed file once (sha256 and received-at); refuse a re-submission; validate vocabulary, BOM and blanks. `label_source: manual`.
- **Stop here (end of Part A)** and print the sheet path.

### 6. Analysis (Part B, after Karan returns the sheet) → `reports/p3002_t4_repass_audit.md` and `reports/p3002_metrics_v1.json`
- **Scores by type:** mean RePASs and each component per answer type, with a seeded 2,000-resample bootstrap 95% CI (n = 30).
- **Paired differences:** concatenated − genuine, and each adversarial type − genuine.
- **Gameability verdict:**
  - "reproduces" if the concatenated − genuine CI lies entirely at or above 0;
  - "does not reproduce" if it lies entirely below 0;
  - otherwise "inconclusive at n = 30".
  - The same logic applies to each adversarial type.
- **Human vs metric:**
  - mean human scores per type;
  - Spearman ρ between RePASs and `faithful`, with n and a bootstrap CI;
  - human-rating minutes per answer, from the log.
- **One minimal repair,** declared exploratory:
  - a penalty proportional to verbatim overlap with the retrieved passages (LCS ratio above a τ fixed in config **before scoring**);
  - plus a question-relevance term from the same NLI model (question ⇒ answer);
  - report whether the repaired score ranks genuine above concatenated, with CIs;
  - **caveat:** τ and the repair were designed with the RIRAG finding in mind and are tested on the same 30 questions, so the result is optimistic.
- **Examples:** 3 per type, with scores.
- **Limitations:** n = 30; one rater; LLM-drafted questions (report the `bad_question` count); a repair not validated on held-out data; the model id(s) used.
