# Command Center (ui/): decisions log

These decisions were taken without asking, as the run instructions require. Where something was ambiguous, the most conservative option was chosen. Part A decisions are in `reports/final/PART_A_DECISIONS.md`.

| # | Decision | Why |
|---|---|---|
| D-01 | **Confidence is calibrated for comparator verdicts only.** Other systems' answers show "not calibrated". | The comparator is the product's verdict engine. Calibrating every system would multiply small-n bands. |
| D-02 | **Two confidence models.** M2 (comparator-intrinsic) is fitted on the 30-item dev set (92 units) and frozen before the gold evaluation. M1 (full signals) is 5-fold cross-fitted on gold, grouped by item. **User instruction (2026-10-03): the Showcase and all product badges (Obligation Explorer, assistant, live mode, review queue) use M2 only.** M1 may appear only in research views, labelled "cross-validated on gold". Every badge tooltip names the model that produced it. | The dev set has predictions for the comparator only (G-25). Keeping product claims on the cleanly held-out model is the stricter choice. |
| D-03 | Band cut points are fixed probabilities (High ≥ 0.85, Medium 0.60–0.85, Low < 0.60), declared in the spec before evaluation. The operating point is "answer at High only". | Nothing is tuned on gold. Dev is too small (92) to tune thresholds. |
| D-04 | The signal "BM25 and dense agree on the matched paragraph" is dropped. The retrieval-support signal is "the comparator's matched paragraph equals the class-aware LLM's matched paragraph". | No per-unit BM25/dense rankings are stored for T1 units (G-23). Recomputing them would need the dense encoder from outside the repo. |
| D-05 | **Per-paragraph word budget.** At most 25 RBI words per paragraph across all bundled uses: a 12-word excerpt, plus comparator field values trimmed to the remaining budget, differing fields first. | "Show at most 25 words of any paragraph." |
| D-06 | Gold fields `raters`, `applies_to_rationale` and `provenance` are not ingested. The annotation sheets (whose filenames carry names) are never read. The comparator's "shown candidates" come from its sealed `per_candidate` field instead of the sheet. | Privacy rule. |
| D-07 | **The claims auditor matches against public sources only:** `results_v2.json`, `error_analysis_v1.json`, public phase metrics, bib numbers and the venue file. Numbers that match nothing are shown as "? not in public sources" and are not counted as ✗ drift unless they look like a metric value (≥ 2 decimals). | `reports/private/` must not be read (G-22). |
| D-08 | **Live pipeline retrieval.** The real class-aware RRF (`src/retrieval/systems.run_query`) over `data/processed` and the stored bge paragraph embeddings. **User instruction (2026-10-03):** free-text queries are embedded locally with the pinned `BAAI/bge-base-en-v1.5` revision `a5beb1e3e68b9ab74eb54cfd186867f64f240e1a`, through the repo's own `src/retrieval/index.load_model`, with HF offline mode first. Stored embeddings are used only for existing benchmark paragraphs. An end-to-end test runs a new, unseen query string through encode → class-aware RRF → comparator (mocked LLM). | This supersedes the earlier BM25-only fallback for free text, and also resolves the memory note's open question about the model cache. |

The verdict comes from `src/rag/comparator_rule.class_verdict`, the frozen sha-verified file, in the Python bridge. The LLM call happens only in the Node proxy, with `ASSISTANT_GEMINI_API_KEY`. | One frozen rule, one key path, no experiment quota. |
| D-10 | The assistant and live mode are OFF by default. Two switches are needed: the settings toggle in the UI and the key present server-side. The daily cap defaults to 50 (`ASSISTANT_DAILY_CAP`). The cache is keyed by sha256 of the prompt. | §8.3. |
